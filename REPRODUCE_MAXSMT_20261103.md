## Fixed cohort

Use `exp2.zip` inside the published archive, with replica counts N=2,11,21
and preferences per replica p=6,8,12. Include every released input in each
selected group: indices 1–100 for p=6,12 and 1–200 for p=8. This gives 1,200
candidate files. `exp2/2N12P/Experiment_2/100.smt2` is an empty placeholder:
it contains no declarations, hard constraints, or soft constraints. Preserve
that original under `excluded_inputs/`; the experiment has 1,199 valid models
(399,400,400 at the three scales). No cases are selected by solver outcomes.

The models combine the published meeting-scheduling goal model with
contribution, conflict, and preference relations. They are application-model
benchmarks generated by the source authors, rather than an industrial trace
collection. The three original lexicographic objectives are, in order,
`unsat_preferences`, `unsat_requirements`, and `sat_tasks` (PRT).

## Solver interfaces

Four configurations use Z3 5.3.3 (MaxRes, WMax) and OptiMathSAT 1.7.4
(default OMT, MaxRes). Each call has a 600-second wall limit, one hardware
thread, and a 4-GiB address-space limit. Six calls run on separate physical
cores 0,2,4,6,8,10; input handling and witness checking use cores 12,14.

Original CGM files use additional `assert-soft` groups to define numeric
attributes (`workTime.Auto`, `cost.Auto`, and `weightVar.Auto`). They occur
inside hard arithmetic constraints but are not objectives. OptiMathSAT
supports these groups natively, so its adapter retains their original
commands and ordering. Z3 implicitly optimizes every soft group; its adapter
therefore expands only the non-objective groups into exact `ite` sums and
keeps the three actual objectives as native soft constraints in PRT order.
Every original hard constraint and every weight is preserved. Diagnostic
numeric expansions tested with OptiMathSAT are archived separately under
`runs/maxsmt_public_20261103/`; they are not manuscript experiment results.

OptiMathSAT uses `-optimization=TRUE -opt.priority=lex`, with
`-opt.maxsmt_engine=omt -unsat_core_generation=0` or
`-opt.maxsmt_engine=maxres -unsat_core_generation=1`. The proof-based core
option is enabled only for MaxRes. Z3 uses `opt.priority=lex` and
`opt.maxsat_engine=maxres` or `wmax`.

## Run and inspect

```bash
python3 scripts/maxsmt_public_20261103.py prepare
python3 -u scripts/maxsmt_public_20261103.py run
python3 scripts/maxsmt_public_20261103.py summarize
python3 scripts/maxsmt_public_20261103.py table
```

The existing Z3 installation is `/tmp/gomt-z3-5.3.3/`; OptiMathSAT is under
`tools/optimathsat-1.7.4-linux-64-bit/`. Use the matching Z3 Python bindings
for witness checks. The runner imports the existing SMT expression reader
from `scripts/nra_public_20261102.py`.

Results are under `runs/maxsmt_cgm_20261103/`. `manifest.json` records
archive/member hashes, scales, original indices, objectives, and binaries.
Every cell retains the solver command, input hash, resource settings,
elapsed time, return code, stdout, stderr, and validation result. A normal
optimized SAT return counts as optimal only after its complete assignment
satisfies the original hard constraints and the three costs recomputed from
the original soft constraints. Hard UNSAT is a completed result; trailing
model queries then have no model and do not invalidate the UNSAT status.
The summary checks agreement of every reported optimal vector and detects
SAT/UNSAT disagreements. Timing excludes preparation and witness checking.

The MaxSMT table reports completion (optimal or hard UNSAT) and median call
time. Calls without a conclusive result contribute infinity to the median.
Existing numeric and performance experiment results are unchanged.

## Automatic manuscript update in this workspace

`python3 scripts/finish_maxsmt_20261103.py supervise` monitors the full matrix,
resumes an externally stopped runner from completed cells, and waits for all
4,796 records. It preserves interrupted logs before restarting. Once the
matrix is complete and the runner has exited, it checks input hashes,
witnesses, statuses and objective agreement, generates the table, and fills
only the reserved MaxSMT block in the sibling `gomt/omt-survey/` manuscript.
The result paragraph reports completed counts; it adds no new general claim.

The pipeline then regenerates citation statistics, builds the PDF, runs the
abstract-freeze and citation/build checks, verifies that the table is within
one page of its discussion, and renders those pages. State and checks are
recorded in `runs/maxsmt_cgm_20261103/automatic_update.json`; previews are in
that directory's `preview/`. It preserves an author-edited reserved block
instead of overwriting it. To cancel this background workflow, create
`runs/maxsmt_cgm_20261103/CANCEL_AUTOMATIC_UPDATE`.

## Server full matrix used by the manuscript

At the author's request, the same complete matrix also ran independently on
`panda1.ios.ac.cn` (Intel Xeon Platinum 8153, 1.8 TiB RAM), matching the
2026-10-30 public-FP server environment. The manuscript table uses this server
run, not a mixture of server and local timings. It started with 32 workers and
continued with 64 workers after 3,264 completed calls; the manifest records
both core sets and the controlled restart. Every solver call remained
single-threaded with a 600-second limit and a 4-GiB address-space limit.

The server driver is `scripts/maxsmt_server_20261103.py`. Its run directory is
`runs/maxsmt_cgm_server_20261103/`; the local copy contains the manifest, all
raw solver outputs, final records, summary, table and interrupted-call logs,
while omitting a duplicate copy of the 7,194 generated inputs. The joint
SHA-256 of those inputs was identical on the two machines:

`9b68d8a318671ae527928b9f466a4d744981627a2f37eae1f87534f2574f4629`.

```bash
python3 scripts/maxsmt_server_20261103.py prepare
python3 -u scripts/maxsmt_server_20261103.py run
python3 scripts/maxsmt_server_20261103.py table
python3 scripts/maxsmt_server_20261103.py status
```

The two initial validation timeouts were preserved and independently rechecked
with `scripts/maxsmt_server_revalidate_20261103.py`. Both exact checks returned
SAT with objective vector `(13,48,189)` in about 0.13 seconds on an otherwise
idle core. Their original records, raw outputs and retry records are retained.
The final 4,796 records contain 4,159 optimal, 164 hard-UNSAT and 473 timeout
calls. Coverage, input hashes, witness flags and objective agreement were
checked after the run. The independent local experiment remains available as
a control; overlapping optimal vectors and SAT/UNSAT decisions showed no
conflicts.
