## 数据范围

- FP：Trentin–Sebastiani JAR 2021 的固定 Docker 数据层，原始 bench/ 全部 17,314 个文件；沿用原作者 run_translation.sh 的目标构造，保留 31 个原始已标注 UNSAT 的输入，不运行 run_filter.sh。生成器使用完整绝对路径，避免 bench 误匹配 benchmarks。完整清单共 39,655 项：原生成器产生 39,638 项，补齐未识别目标的 16 项，再加入发布包中一个内容不同的优化输入；发布的 o300/ 共 1,120 项，其中 1,119 项与生成结果完全相同，以别名记录，不重复计为性能观测。全部 17,314 个原始文件都有派生任务与源文件哈希。不得将 o300 当成未抽样的原始全集。
- 原生 BV：Nadel–Ryvchin TACAS 2016 作者公开的完整实验包，包含基准和历史结果；基准与历史结果分别识别，全部 254 个原生 BV 实例进入固定清单。另将原包全部 254 个整数伴随文件按其原始多目标语义完整运行，作为独立诊断。整数文件的词典序目标与值域须单独核对，不能直接当作 BV 的等价编码做性能比较。
- MaxSMT：He 等 FM 2024 PairLS 作者公开实验包，公开 release 实际含 2,264 个 LIA 标准输入（283 个基础问题 × 4 种软约束比例 × 2 种权重设置），全部运行，不把 ls_format 副本重复计数。公开包没有 IDL、LL 或 bofill 家族；不能将这 2,264 例称为论文中 5,520/12,888/114 例实验的完整复现。

## 实验口径

采用每次求解 600 秒、单线程、8 GiB 地址空间上限；每个 ExperimentOS 作业申请 16 GiB 上限以容纳适配器和求解器子进程，遵守平台空闲资源调度。完整固定清单先于性能运行，运行环境、源文件/求解器/脚本哈希、命令和原始日志均留存。主比较的求解器在同一输入所在机器上运行，避免跨硬件直接比较。FP、BV、MaxSMT 的每条独立验证查询预算为 60 秒，与求解时间分别报告。FP 比较全部排除 NaN 目标，键编码额外细分 -0 与 +0；源文件原样保留。MaxSMT 比较 OptiMathSAT MaxRes/OMT 与 Z3 MaxRes/WMax 四种配置。整数伴随文件使用明确的词典序模式，保留完整界与原始输出，不将 SAT 或打印出的模型直接称为最优解。超时、内存不足、解析错误、无解和未验证结果都保留在总分母中。预检仅检查管线，不替代全集实验；全部计划任务产生终态并核对覆盖率后才算完成。

## 输入有效性审计

MaxSMT 的 2,264 个原始标准输入已全部解析核对：2,245 个通过；8 个 query-901 变体含非法符号和不完整语法，另 11 个文件在 262,144 字节处被截断。损坏在原始 RAR 中已经存在，本地与控制节点内容一致。全部 19 个保留在清单和分母中，实际调用每种求解器记录原始拒绝响应，标为 `invalid_input`，不猜测补写约束，不伪造最优值。完整发布包计数、有效输入计数与已证最优计数分别报告。

FP 的 16 个补充任务中，14 个来自原生成器未识别的 FP 目标，另 2 个来自原包中一个仅含元数据、`check-sat` 和 `exit` 的空公式文件。后者以常量 binary32 正零分别构造最小化和最大化任务，明确标为退化的可行性检查，不据此讨论浮点运算性能。补充规则、源文件哈希和输出文件哈希见 `benchmarks/full_public/fp-supplement.json`。补充程序可重复执行并保留既有生成记录。

`snapshot.py` 按实例编号、源哈希和求解配置核对完整覆盖，另外比较求解器所报最优值；FP 比较将有符号零视为原生数值序下的等值。`archive_results.py` 只收集本轮实验目录，保存每个文件哈希、运行环境、输入来源和原始输出；不会打包控制面配置或凭据。所有任务终止且覆盖审计通过前，进度汇总的 `all_inputs_completed` 为假。

整数伴随文件的初次审计触发了单目标适配器的多目标断言；这是适配器范围不匹配，不属于源文件语法损坏。新的 `run_lia_diagnostic.py` 保留全部整数约束与目标顺序，对两个求解器显式设置词典序模式（OptiMathSAT 默认是盒式，不能沿用默认值）。有界、无界、不可满足的三类已知答案例在两款求解器上均通过。原包的 `size_10_10_density_20_9.xml_lia.smt2` 还存在可核对的上无界参数族：固定可行布局后，六个整数目标均可随任意整数参数增大；对应 BV 目标只有六位。`audit_lia_semantics.py` 从原始文件重建并验证此证书，完整输入仍各自运行。本组仅报告原始文件的语义诊断，不据此比较 BV/LIA 的求解速度。

## 执行节点环境

`environment-inventory.json` 保存了所有已有成功作业的执行节点的环境记录：原始作业记录中的 CPU、内核、Python、求解器二进制哈希及 CPU 亲和性，以及有独立观测时间的操作系统补充探测。当前覆盖 10 个节点：Panda1/2 为 Ubuntu 26.04，Panda3/4/5/7/8/9 和 Tiger7 为 Ubuntu 24.04，Panda6 为 Ubuntu 22.04。Panda1–7 为 Xeon Platinum 8153，Panda8 为 AMD EPYC 7702，Panda9 为 Xeon Gold 6248，Tiger7 为 Xeon Gold 5215。此次机群环境与原稿的 WSL 参数化实验分别报告。

每个输入的全部配置在同一节点顺序运行；按输入 ID 奇偶翻转配置顺序，与求解结果无关。跨输入的节点可以不同，因此比较依据是同一输入上的配对观测，不把所有运行说成同一型号机器。全部原始作业归档完成后还需核对是否有新增节点，并重新生成该环境清单。

## 全量检查与主稿准备

`input-commands-audit.json` 逐文件核对全部 254 个 BV 输入与 254 个整数伴随输入的目标方向和选项指令。所有原始目标均为最大化，源文件均没有 `set-option` 指令覆盖显式指定的优化优先级。该检查只读取冻结输入，不改变问题或选择性能样本。

`paper-methods-draft.tex` 是尚未并入主稿的方法说明草稿，不含性能结果。完整运行、原始日志归档与覆盖审计全部通过后，再结合最终结果表精简并入 LaTeX 主稿。

整数伴随实验遇到的输入暂存故障、完整哈希修复和 7 个原任务的基础设施重试记录见 [staging-incident/README.md](staging-incident/README.md)。失败尝试的日志与工作目录均保留；其余实验和冻结求解协议不受改动。

`status-reviews.json` 保存基于原始输出的终态分类复核。冻结的整数诊断程序把 OptiMathSAT 在标准输出中的 `(error "std::bad_alloc")` 记为通用 `solver_error`；统计后处理将这一精确响应及返回码匹配的情况细分为 `oom`，仍属未求解结果。分类同时绑定原指标、输入哈希、运行环境与原始响应哈希，归档时再次逐项核对；原平台状态、指标和日志不重写，CSV 同时保留 `reported_status` 与复核后的 `status`。其他未知错误继续阻止最终汇总。内存分配失败不重跑、不从分母删除，也不等同于缺失输入的基础设施失败。
